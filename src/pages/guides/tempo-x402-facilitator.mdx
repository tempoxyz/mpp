# Get paid on Tempo for x402 payments [Use the Tempo x402 facilitator]

The Tempo x402 facilitator settles standard x402 payments and pays you the same amount on Tempo.

- Buyers keep paying with any x402 client
- Only your server's facilitator settings change
- Already accept MPP on Tempo? You're paid on Tempo directly and don't need it

## Supported payment networks

| Direction | Network | Chain ID | Token | Schemes |
| --- | --- | --- | --- | --- |
| Pay in | Base mainnet | `eip155:8453` | [USDC](https://basescan.org/token/0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913) | `exact` (EIP-3009 or Permit2) |
| Pay out | Tempo mainnet | `eip155:4217` | [OUSD](https://explore.tempo.xyz/address/0x20c0000000000000000000006a37da5c996874be) | — |

`GET /v1/x402/supported` lists what the facilitator accepts right now.

## How it works

<MermaidDiagram chart={`sequenceDiagram
    participant Buyer
    participant Seller
    participant Tempo as Tempo facilitator
    Buyer->>Seller: (1) GET /resource
    Seller-->>Buyer: (2) 402 Payment Required
    Buyer->>Seller: (3) Retry with signed USDC
    Seller->>Tempo: (4) Verify and settle
    Note over Tempo: (5) Settle USDC on Base, send OUSD on Tempo
    Tempo-->>Seller: (6) Base and Tempo hashes
    Seller-->>Buyer: (7) 200 OK
`} />

1. Your route offers an `exact` USDC payment to Tempo's deposit address (`payTo`).
2. `extra.tempoSettlement` names your Tempo payout address.
3. The buyer signs as for any x402 facilitator.
4. The facilitator settles on Base, then sends the same amount in OUSD to your payout address.
5. The settle response returns both hashes.

## Quickstart

### Get a Tempo API key

- Create a [Tempo API](https://tempo.xyz/developers/docs/api/mpp) key with the `mpp:write` scope
- Send it in the `tempo-api-key` header (or as `Authorization: Bearer`) on every call
- Use a production key: sandbox keys get `403 production_api_key_required`

### Register your payout address

The facilitator refuses payments to an unregistered Tempo address.

```bash [test.sh]
$ curl -X POST https://api.tempo.xyz/v1/x402/payout-addresses \
    -H "tempo-api-key: $TEMPO_API_KEY" \
    -H "content-type: application/json" \
    -d '{"address":"0x742d35Cc6634C0532925a3b844Bc9e7595f8fE00","label":"Main payouts"}'
```

- Registering again returns the existing registration
- List addresses with `GET /v1/x402/payout-addresses`
- Remove one with `DELETE /v1/x402/payout-addresses/{address}`

### Point your server at the facilitator

Change three things:

- **Facilitator**—`https://api.tempo.xyz/v1/x402`, with your API key
- **`payTo`**—the deposit address from `/supported`
- **`extra.tempoSettlement`**—your registered Tempo payout address

```ts [Next.js]
import { HTTPFacilitatorClient, x402ResourceServer } from '@x402/core/server'
import { ExactEvmScheme } from '@x402/evm/exact/server'
import { withX402 } from '@x402/next'
import { NextResponse } from 'next/server'

const network = 'eip155:8453' // Base mainnet
const headers = { 'tempo-api-key': process.env.TEMPO_API_KEY! }

const facilitator = new HTTPFacilitatorClient({
  createAuthHeaders: async () => ({ settle: headers, supported: headers, verify: headers }),
  url: 'https://api.tempo.xyz/v1/x402',
})

// Tempo's deposit address on Base
const { kinds } = await facilitator.getSupported()
const payTo = kinds.find((kind) => kind.network === network && kind.scheme === 'exact')
  ?.extra?.payTo as string

const server = new x402ResourceServer(facilitator).register(network, new ExactEvmScheme())

export const GET = withX402(
  async () => NextResponse.json({ data: 'premium content' }),
  {
    accepts: {
      extra: { tempoSettlement: '0x742d35Cc6634C0532925a3b844Bc9e7595f8fE00' },
      network,
      payTo,
      price: '$0.01',
      scheme: 'exact',
    },
  },
  server,
)
```

Buyers change nothing: any x402 client, including `@x402/fetch` and the [`mppx` client](/guides/use-mpp-with-x402#client), pays these routes.

### Check the payout

The settle response returns the Base hash in `transaction` and the Tempo payout under `extensions.tempoSettlement`:

```json
{
  "success": true,
  "transaction": "0x…",
  "network": "eip155:8453",
  "extensions": {
    "tempoSettlement": {
      "amount": "10000",
      "payoutId": "x402pay_…",
      "status": "submitted",
      "to": "0x742d35Cc6634C0532925a3b844Bc9e7595f8fE00",
      "token": "0x20c0000000000000000000006a37DA5C996874BE",
      "transaction": "0x…"
    }
  }
}
```

- The Tempo hash never changes, even if the transaction is rebroadcast
- Settle returns once the payout is broadcast, not confirmed
- To confirm, poll `GET /v1/x402/payouts/{payoutId}` until `status` is `confirmed`
- Or look it up by Base hash with `GET /v1/x402/settlements/{transaction}`

## Reference

### Endpoints

All routes live under `https://api.tempo.xyz/v1/x402` and take your API key.

| Route | Purpose |
|---|---|
| `GET /supported` | x402 supported kinds. Each kind's `extra` carries the deposit address (`payTo`) and the Tempo network and token paid out |
| `POST /verify` | Standard x402 verify |
| `POST /settle` | Standard x402 settle, plus `extensions.tempoSettlement` |
| `POST /payout-addresses` | Register a Tempo payout address: `{ address, label? }` |
| `GET /payout-addresses` | List your payout addresses |
| `DELETE /payout-addresses/{address}` | Remove a payout address |
| `GET /payouts/{id}` | Payout status and Tempo hash |
| `GET /settlements/{transaction}` | Settlement and payout by Base hash |

### Amounts and limits

- **Networks**: see [Supported payment networks](#supported-payment-networks)
- **Amount**: the payout equals the amount settled on Base. No fee today; any fee is announced before it applies
- **Limits**: the minimum payment is 0.01 USDC. Verify refuses amounts outside the limits

### Errors

Verify and settle answer HTTP `200` with `isValid: false` or `success: false` and a reason, per the x402 facilitator contract.

| Reason | Fix |
|---|---|
| `payto_not_deposit_address` | Set `payTo` to the deposit address from `/supported` |
| `missing_tempo_settlement` | Add `extra.tempoSettlement` to the payment requirements |
| `payout_address_not_registered` | Register the address with `POST /payout-addresses` |
| `amount_below_minimum`, `amount_above_maximum` | Price the route within the limits |
| `insufficient_tempo_liquidity` | Temporary—retry later |
| `settlement_pending` | The Base settlement hasn't confirmed yet—retry the same settle request |

Retrying a settled payment returns the same response and never settles or pays twice.

# Client [Handle `402` responses automatically]

The `Fetch` extension trait selects a supported Challenge, creates a Credential, and retries a `reqwest` request.

## Quick start

```rust
use mpp::client::{Fetch, TempoProvider};
use mpp::PrivateKeySigner;

let signer = PrivateKeySigner::random();
let provider = TempoProvider::new(signer, "https://rpc.tempo.xyz")?;

let response = reqwest::Client::new()
    .get("https://api.example.com/paid")
    .header("Accept-Payment", "tempo/charge")
    .send_with_payment(&provider)
    .await?;
```

The default `AcceptPaymentPolicy::Explicit` pays only when the request has an `Accept-Payment` header. This keeps requests to untrusted URLs from authorizing payment implicitly.

## Middleware

```toml
mpp = { version = "0.18.1", features = ["client", "middleware", "tempo"] }
```

```rust
use mpp::client::{PaymentMiddleware, TempoProvider};
use reqwest_middleware::ClientBuilder;

let provider = TempoProvider::new(signer, "https://rpc.tempo.xyz")?;
let client = ClientBuilder::new(reqwest::Client::new())
    .with(PaymentMiddleware::new(provider))
    .build();

let response = client
    .get("https://api.example.com/paid")
    .header("Accept-Payment", "tempo/charge")
    .send()
    .await?;
```

Request-level payment authorization is still required with middleware. Default headers on the `reqwest` client do not authorize payment.

## Multiple providers

```rust
use mpp::client::{MultiProvider, TempoProvider};

let provider = MultiProvider::new()
    .with(TempoProvider::new(signer, "https://rpc.tempo.xyz")?);
```

`MultiProvider` selects by method and intent while preserving the order of the client's `Accept-Payment` preferences.

## Event handling

```rust
use mpp::client::{ClientEventKind, ClientEvents};

let events = ClientEvents::default();
let _subscription = events.on(ClientEventKind::PaymentResponse, |event| async move {
    println!("payment event: {}", event.kind().as_str());
});
```

Retain subscription handles while handlers are active.

## Custom providers

Implement `PaymentProvider` for another payment method. Its `pay` method receives a typed `PaymentChallenge` and returns a `PaymentCredential`. Validate the complete Challenge, enforce spending limits, and preserve the Challenge echo unchanged.

## Key types

| Type | Description |
|---|---|
| `AcceptPaymentPolicy` | Controls which requests authorize automatic payment |
| `Fetch` | Adds `send_with_payment` to `reqwest::RequestBuilder` |
| `MultiProvider` | Routes Challenges to supported providers |
| `PaymentMiddleware` | Adds payment handling to `reqwest-middleware` |
| `PaymentProvider` | Interface for payment implementations |
| `TempoProvider` | Creates Tempo charge Credentials |

# Server [Protect endpoints with payment requirements]

Configure an `Mpp` handler once, issue Challenges for each route price, and verify the retry against that same price.

## Quick start

```rust
use mpp::server::{tempo, Mpp, TempoConfig};
use mpp::{format_www_authenticate_many, parse_authorization};

let payment = Mpp::create(tempo(TempoConfig {
    recipient: "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
}))?;

let challenges = payment.charge("0.50")?;
let headers = format_www_authenticate_many(&challenges)?;

let credential = parse_authorization(authorization)?;
let receipt = payment.verify_charge(&credential, "0.50").await?;
```

Return every Challenge header value. Tempo accepts multiple currencies by default and `charge` returns one Challenge for each currency.

Always use `verify_charge` with the route's price. The deprecated `verify_credential` alias accepts a Credential for any route created by the handler and can permit cross-route replay between different prices.

## Configure Tempo

```rust
use mpp::protocol::methods::tempo::PATH_USD;
use mpp::server::{tempo, Mpp, TempoConfig};

let payment = Mpp::create(
    tempo(TempoConfig {
        recipient: "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
    })
    .chain_id(42431)
    .currencies([PATH_USD])
    .realm("api.example.com")
    .rpc_url("https://rpc.moderato.tempo.xyz")
    .secret_key("replace-with-at-least-32-bytes-of-secret-material"),
)?;
```

Use `.currencies(...)`; the singular `.currency(...)` builder is deprecated. Keep `MPP_SECRET_KEY` in a secret manager. It must contain at least 32 bytes.

For production replay protection, configure a shared persistent `Store` across every replica. The default memory store is process-local and loses state on restart.

## Existing `Authorization` headers

```rust
let payment = Mpp::create(tempo(config).requires_auth(true))?;
```

Challenges then advertise `Payment-Authorization`. Use a redirect-disabled transport for credential-bearing requests until the high-level reqwest helpers support a verified redirect-safe client for this header.

## Charge options

```rust
use mpp::server::ChargeOptions;

let challenges = payment.charge_with_options(
    "1.00",
    ChargeOptions {
        description: Some("Premium content"),
        external_id: Some("order-123"),
        ..Default::default()
    },
)?;

let receipt = payment
    .verify_charge_with_options(
        &credential,
        "1.00",
        ChargeOptions {
            description: Some("Premium content"),
            external_id: Some("order-123"),
            ..Default::default()
        },
    )
    .await?;
```

Pass the same options during issuance and verification.

## Axum extractor

With the `axum` feature, `MppCharge<C>` issues `402` responses and extracts a verified Receipt:

```rust
use mpp::server::axum::{ChargeConfig, MppCharge};

struct OneCent;

impl ChargeConfig for OneCent {
    fn amount() -> &'static str {
        "0.01"
    }
}

async fn paid(charge: MppCharge<OneCent>) -> String {
    charge.receipt.reference
}
```

Use `MppChargeWithBody<C>` for body-bound paid requests.

## Sessions

Tempo sessions require a `SessionMethod` and durable channel storage. Generate route Challenges with `session_challenge_with_details`, verify vouchers with `verify_session`, and forward management responses for channel operations.

## Key types

| Type | Description |
|---|---|
| `ChargeOptions` | Route-specific charge configuration |
| `Mpp` | Server payment handler |
| `MppCharge` | Axum extractor for paid routes |
| `SessionChallengeOptions` | Session Challenge configuration |
| `TempoChargeMethod` | Tempo charge verifier |
| `TempoConfig` | Tempo server configuration |

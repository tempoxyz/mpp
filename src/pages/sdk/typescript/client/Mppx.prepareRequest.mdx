# `Mppx.prepareRequest` [Prepare a request before payment]

Returns the exact HTTP request and response, plus a prepared payment when required.

## Usage

```ts twoslash [client.ts]
import { Mppx, tempo } from 'mppx/client'
import { privateKeyToAccount } from 'viem/accounts'

const mppx = Mppx.create({
  methods: [
    tempo({
      account: privateKeyToAccount(
        '0x0123456789012345678901234567890123456789012345678901234567890123',
      ),
    }),
  ],
  polyfill: false,
})

// [!code hl:start]
const prepared = await mppx.prepareRequest('https://api.example.com/checkout', {
  body: JSON.stringify({ plan: 'pro' }),
  headers: { 'Content-Type': 'application/json' },
  method: 'POST',
})

console.log(prepared.response.status)
// @log: 402

if (prepared.payment) {
  console.log(`${prepared.payment.challenge.method}/${prepared.payment.challenge.intent}`)
  // @log: tempo/charge
  const response = await prepared.payment.pay()
  console.log(response.status)
  // @log: 200
}
// [!code hl:end]
```

`prepareRequest` sends the request without creating a Credential and follows pre-payment redirects. It returns every HTTP response, including responses that don't require payment. Use it to inspect the response or approve payment terms while keeping any Credential bound to the request that produced the Challenge.

When the response requires payment, `payment` contains the selected Challenge and payment helpers. Otherwise, `payment` is `undefined`.

The method rejects HTTPS downgrade redirects, removes credentials and sensitive headers on cross-origin redirects, and applies standard redirect method changes. `payment.pay` creates the Credential at most once and sends it only to the prepared URL with redirects disabled.

:::warning[Runtime support]
Use `prepareRequest` in Node.js and runtimes that expose manual redirect responses. Browsers return opaque manual redirects, so this method rejects browser redirect chains.
:::

## Advanced options

### Require payment

Set `requirePayment` to reject responses that don't require payment. TypeScript narrows `payment` to a required value.

```ts twoslash [client.ts]
import { Mppx, tempo } from 'mppx/client'
import type { Account } from 'viem'

declare const account: Account

const mppx = Mppx.create({
  methods: [tempo({ account })],
  polyfill: false,
})

// [!code hl:start]
const prepared = await mppx.prepareRequest(
  'https://api.example.com/paid',
  undefined,
  { requirePayment: true },
)
// [!code hl:end]

const response = await prepared.payment.pay()
```

### With request-local selection

Override the configured payment preferences for one request.

```ts twoslash [client.ts]
import { Mppx, tempo } from 'mppx/client'
import type { Account } from 'viem'

declare const account: Account

const mppx = Mppx.create({
  methods: [tempo({ account })],
  polyfill: false,
})

// [!code hl:start]
const prepared = await mppx.prepareRequest(
  'https://api.example.com/paid',
  undefined,
  {
    acceptPayment: 'tempo/charge;q=1, tempo/session;q=0',
    maxRedirects: 5,
    orderChallenges: (candidates) => candidates.filter(({ challenge }) =>
      challenge.request.amount !== '0'
    ),
    requirePayment: true,
  },
)
// [!code hl:end]

console.log(`${prepared.payment.challenge.method}/${prepared.payment.challenge.intent}`)
// @log: tempo/charge
```

## Return type

```ts
type PreparedRequest<RequirePayment extends boolean = false> = Readonly<{
  payment: RequirePayment extends true
    ? PreparedRequest.Payment
    : PreparedRequest.Payment | undefined
  redirects: readonly Readonly<{
    from: string
    status: number
    to: string
  }>[]
  request: Request
  response: Response
}>

declare namespace PreparedRequest {
  type Payment = Readonly<{
    challenge: Challenge
    challenges: readonly Challenge[]
    createCredential: (context?: Context) => Promise<string>
    method: Method.Client
    pay: (context?: Context) => Promise<Response>
    setCredential: (request: RequestInit, credential: string) => RequestInit
  }>
}
```

### payment

The selected payment when `response` requires payment. This value is required when you pass `requirePayment: true`; otherwise, it can be `undefined`.

#### challenge

The selected immutable Challenge.

#### challenges

All supported Challenges extracted from the payment-required response.

#### createCredential

Creates the selected Challenge's Credential. Repeated or concurrent calls return the same promise.

#### method

An immutable snapshot of the configured client method selected for the Challenge.

#### pay

Creates and sends the Credential to the prepared request. The paid request uses `redirect: 'manual'`, so the Credential doesn't follow a redirect to another URL.

#### setCredential

Returns a request initializer with the Credential attached through the protocol that produced the Challenge.

### redirects

Immutable pre-payment redirect records with each source URL, status code, and destination URL.

### request

The exact request that returned `response`.

### response

The response returned for `request`.

## Parameters

### init (optional)

- **Type:** `RequestInit`

Request options for the initial HTTP request.

### input

- **Type:** `RequestInfo | URL`

URL or request to prepare.

### options (optional)

- **Type:** `{ acceptPayment?: string | readonly AcceptPayment.Entry[]; maxRedirects?: number; orderChallenges?: OrderChallenges; requirePayment?: boolean }`

Request-local Challenge selection and redirect limits.

- `acceptPayment` overrides the configured payment preferences.
- `maxRedirects` sets the maximum pre-payment redirects. Defaults to `20`.
- `orderChallenges` filters or sorts supported Challenge candidates.
- `requirePayment` rejects responses that don't require payment. Defaults to `false`.

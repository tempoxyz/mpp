# `Store.tryClaim` [Claim replay keys atomically]

Records the first use of a replay key until its expiration time.

## Usage

```ts twoslash
import { Store } from 'mppx'

const store = Store.memory()
const expires = Date.now() + 60_000

const claimed = await Store.tryClaim(store, 'request:abc123', expires) // [!code hl]
console.log(claimed)
// @log: true

const replayed = await Store.tryClaim(store, 'request:abc123', expires)
console.log(replayed)
// @log: false
```

An `AtomicStore` is a key-value store with indivisible per-key `update(key, fn)` operations. The update callback reads the current value (or `null`) and returns a change plus a result; concurrent updates can't both commit against the same old value.

`Store.tryClaim` uses the store's optional optimized `tryClaim` operation when present. Otherwise, it falls back to `AtomicStore.update`. Expired replay markers can be claimed again; legacy non-marker values remain claimed. Non-finite or already-expired proposed expiries return `false`. The optimized path also checks expiry after the operation completes, so a claim that expires in flight returns `false`.

### Support replay claims in a custom store

`AtomicStore` accepts an optional `tryClaim` fast path. Reject non-finite expiries and check `expires <= Date.now()` inside the atomic operation, not only before asynchronous work. The fallback stores a `ReplayMarker`, so include that type in a custom store's item map when you don't provide the fast path.

```ts
type TryClaim<itemMap extends StoreItemMap = StoreItemMap> = <
  key extends keyof itemMap & string,
>(key: key, expires: number) => boolean | Promise<boolean>

// [!code hl:start]
type ReplayMarker = {
  expires: number
  type: 'mppx:replay'
}
// [!code hl:end]
```

### Compose a native claim implementation

Spread a Redis or Upstash adapter into `Store.from`, then add a native `tryClaim` operation. The wrapper preserves the fast path and applies `keyPrefix` to claim keys.

```ts [store.ts]
import { Store } from 'mppx'

const adapter = Store.upstash({
  del: (key) => redis.del(key),
  get: (key) => redis.get(key),
  set: (key, value) => redis.set(key, value),
  update: (key, fn) => atomicUpdate(redis, key, fn),
})

const store = Store.from(
  {
    ...adapter,
    // [!code hl:start]
    async tryClaim(key, expires) {
      if (!Number.isFinite(expires) || expires <= Date.now()) return false
      const result = await redis.set(key, { expires, type: 'mppx:replay' }, {
        nx: true,
        pxat: expires,
      })
      return result === 'OK'
    },
    // [!code hl:end]
  },
  { keyPrefix: 'mppx:' },
)
```

Use an absolute Unix-millisecond expiry such as Upstash `pxat` or Redis `PXAT`, not a relative duration. The native operation must not create an already-expired claim; use backend-side expiry validation where needed. [SQL stores](/sdk/typescript/core/Store.sql) and [Durable Object stores](/sdk/typescript/core/Store.durableObject) provide built-in claim operations. Durable Object replay sharding groups many expiring claims into reusable objects with a separate claims table. With sharding enabled, claims live separately from ordinary values: `get` doesn't return them, and `delete` releases them.

## Return type

```ts
type ReturnType = boolean | Promise<boolean>
```

Returns `true` when this call records the key and `false` when an unexpired claim already exists or the proposed expiry is invalid or has passed.

## Parameters

### expires

- **Type:** `number`

Finite Unix timestamp in milliseconds when the replay claim expires; it must be in the future.

### key

- **Type:** `string`

Store key to claim. Typed stores constrain this value to their item-map keys.

### store

- **Type:** `Store.AtomicStore`

Atomic store used to persist the replay marker. Implement `store.tryClaim` as a single insert-if-absent-with-expiry operation when your backend supports it.

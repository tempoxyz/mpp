# `Store.durableObject` [Durable Object storage]

Creates a store with indivisible per-key updates and one Durable Object per key.

## Usage

```ts twoslash
import { Store } from 'mppx'

export class MppxStore extends Store.DurableObjectStore {}

type Env = { MPPX_STORE: Store.durableObject.Namespace }

export default {
  async fetch(_request: Request, env: Env) {
    const store = Store.durableObject(env.MPPX_STORE) // [!code hl]
    await store.put('usage:customer-42', { requests: 1 })
    return Response.json(await store.get('usage:customer-42'))
  },
}
```

Bind `MppxStore` as a SQLite-backed class with a `new_sqlite_classes` migration; see [Store.DurableObjectStore](/sdk/typescript/core/Store.DurableObjectStore#usage).

Each key's reads and writes are linearizable across Worker isolates and locations. `update(key, fn)` passes the current value (or `null`) to your synchronous, side-effect-free callback; the callback returns a change and result as described below. The store runs it in the Worker and commits with compare-and-swap in the object. Conflicts retry with jittered backoff, using the value returned by the failed swap, up to the `maxAttempts` option (default `32`), rerunning the callback with that current value.

## Return type

```ts
type ReturnType = Store.AtomicStore
```

`get(key)` returns the stored value or `null`; `put(key, value)` writes it and `delete(key)` removes it. `update(key, fn)` atomically applies a synchronous callback to the current value (or `null`). Return `{ op: 'set', result, value }`, `{ op: 'delete', result }`, or `{ op: 'noop', result }`; the update promise resolves to `result`. The callback can run again on conflict, so keep it free of side effects.

[Store.tryClaim(store, key, expires)](/sdk/typescript/core/Store.tryClaim) records first use of a replay key until a future Unix-millisecond timestamp. It returns `true` for a new claim, or `false` for an existing live claim or invalid expiry; this prevents duplicate requests.

## Parameters

### namespace

- **Type:** `Store.durableObject.Namespace`

Namespace binding of a [Store.DurableObjectStore](/sdk/typescript/core/Store.DurableObjectStore) subclass. Keys normally select `idFromName(key)`; reserved shard-like names and names starting with `mppx:key:` are escaped to avoid object-name collisions.

### options (optional)

- **Type:** `Store.durableObject.Options`

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `encoding` | `'json' \| 'native'` | `'json'` | JSON text or structured-clone values. Native encoding requires RPC. |
| `keyPrefix` | `string` | None | Prefix for every backing key, including replay claims made by [Store.tryClaim](/sdk/typescript/core/Store.tryClaim), which records first use until a Unix-millisecond expiry. |
| `maxAttempts` | `number` | `32` | Maximum compare-and-swap attempts per `update`. |
| `replayShards` | `number` | Disabled | Positive safe integer count of SQLite-backed objects that each hold multiple expiring replay claims. |
| `replayShardVersion` | `number` | `1` | Positive safe integer version in shard object names. |
| `transport` | `'fetch' \| 'rpc'` | `'fetch'` | Fetch requests or Workers RPC method calls. |

Invalid shard counts or versions throw at construction, as does `encoding: 'native'` without `transport: 'rpc'`.

## Advanced options

### Use Workers RPC and native values

Workers RPC only reaches classes derived from Cloudflare's `DurableObject`, so the Worker class must extend the RPC base:

```ts [worker.ts]
import { DurableObject } from 'cloudflare:workers'
import { Store } from 'mppx'

export class MppxStore extends Store.DurableObjectStore.rpc(DurableObject) {}

type Env = { MPPX_STORE: DurableObjectNamespace<MppxStore> }

export default {
  async fetch(_request: Request, env: Env) {
    // [!code hl:start]
    const store = Store.durableObject(env.MPPX_STORE, {
      encoding: 'native',
      transport: 'rpc',
    })
    // [!code hl:end]
    await store.put('usage:customer-42', { requests: 1n })
    return new Response('Saved')
  },
}
```

`json` uses the `ox` library's JSON serialization, including bigint support. `native` preserves structured-clone values and can read values written directly with `storage.put`. Keep one encoding per namespace or key prefix: stored values carry no encoding tag, native clients read old JSON as text, and JSON clients cannot read native values. Migrate values or use a new prefix before switching.

Native compare-and-swap compares values structurally, including cycles and aliasing, arrays, plain objects, typed arrays, buffers, dates, regular expressions, boxed primitives, and primitive-keyed maps and sets. Key or insertion order matters. Object-keyed maps, object-valued sets, views of resizable buffers, and unsupported object types throw rather than endlessly conflicting.

### Shard replay claims

Set `replayShards` to spread short-lived replay claims across reusable SQLite-backed objects named `mppx:replay:v<version>:<shard>`, selected by a stable FNV-1a hash of the prefixed key. Claims live in `mppx_replay_claims` and alarms remove expired rows instead of leaving one object per replay key.

Sharded claims are separate from ordinary values: `get` and `update` don't see them, and a value at the same key doesn't block a claim. `delete` releases both the ordinary key and its shard claim. Reserve replay keys for expiring claims.

Enabling sharding or changing its count or version permits an old, unexpired claim to be claimed again under the new settings. Change settings only when no old claim matters—for example, together with `Mppx.create`'s `secretKey`, which authenticates payment Challenges and invalidates old Challenges when rotated—and bump `replayShardVersion` when changing the count. Don't run different settings side by side while old claims matter.

A subclass's constructor, handlers, and alarms also run in shard objects. Use `isReplayShard()` to skip your own work, never clear shard storage, and call `super.alarm()` when overriding alarms. See [subclass hooks](/sdk/typescript/core/Store.DurableObjectStore#subclass-hooks).

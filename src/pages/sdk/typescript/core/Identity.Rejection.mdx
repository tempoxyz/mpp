# `Identity.Rejection` [Reject an identity]

Rejects the identity a request carries, from an [`Identity.from`](/sdk/typescript/core/Identity.from) lookup.

## Usage

```ts twoslash
import * as Identity from 'mppx/identity'

const member = Identity.from({
  verify(request) {
    if (!request.headers.has('X-Api-Key')) return undefined
    throw new Identity.Rejection('This API key is disabled.', { status: 'forbidden' }) // [!code hl]
  },
})
```

- Return `undefined` or `null` for a request with no identity (`missing`, `401`); throw this error to reject one it carries.
- The message becomes the response body. Don't put secrets or raw provider errors in it.
- Other error classes propagate instead of becoming identity rejections.

## Return type

An `Error` subclass:

```ts
type Rejection = Error & {
  /** @deprecated Read `status`. */
  code: number
  name: 'Rejection'
  status: 'forbidden' | 'invalid' | 'unavailable'
}
```

## Parameters

### message

- **Type:** `string`

Public rejection reason.

### options (optional)

- **Type:** `{ code?: number; status?: 'forbidden' | 'invalid' | 'unavailable' }`
- **Default:** `{}`

#### options.code (optional, deprecated)

- **Type:** `number`

HTTP status of the rejection. Use `status` instead. `403` maps to `forbidden`, `503` to `unavailable`, and any other code to `invalid`, sent with that code.

#### options.status (optional)

- **Type:** `'forbidden' | 'invalid' | 'unavailable'`
- **Default:** `'invalid'`

Fixed status of the rejection. See [`Identity.Status`](/sdk/typescript/core/Identity.Status).

- `invalid` (`401`): the proof didn't verify.
- `forbidden` (`403`): the caller is known, but your policy doesn't allow it.
- `unavailable` (`503`): the identity can't be checked right now, such as during a provider outage.

Any other value throws a `TypeError`.
